What MukhdaX does

MukhdaX is an image-provenance instrument. You submit an image; the server detects faces, searches the public web for visually matching pages, reads metadata from the pages it finds, reduces the evidence to a canonical fingerprint, and can record that fingerprint on the Ethereum Sepolia testnet. It reports provenance evidence, not identity.

Image upload and processing

  • The image you select is sent to the MukhdaX server as part of a verification request (POST /api/verify).
  • The server writes the upload to a temporary file, runs the pipeline, and removes the temporary file when the request settles, whether it succeeds or fails.
  • Supported formats are JPG, PNG, and WebP, up to 10 MB. Files that are unreadable, unsupported, or decode to unreasonable dimensions are refused before any search or recording runs.

Reverse-image discovery

The server forwards the image to its configured reverse-image-search provider (SerpApi Google Lens) for visual matching, and reads metadata from the pages the provider returns. Those pages are public web pages; the metadata read is whatever those pages publicly expose.

Face data

Face detection runs on the server. The raw face embedding is never written on-chain and is never returned as evidence: it is reduced to a SHA-256 fingerprint before it enters the canonical evidence payload.

Blockchain records

When on-chain recording is enabled, exactly one value is written to the Sepolia testnet: a Keccak-256 digest of the canonical evidence payload. The image, the face embedding, and page contents are never written on-chain. Testnet records are public by the nature of the network.

Retention

Uploaded image bytes are held only for the duration of the verification request and are deleted afterwards. MukhdaX keeps no user accounts and stores no raw images or raw embeddings as part of its normal operation. No specific archival retention period is offered here because no archive is kept.

Cookies and tracking

MukhdaX sets no cookies, runs no analytics, and loads no third-party tracking resources. The interface stores nothing in your browser: no localStorage, no sessionStorage, no fingerprinting.

Technical request data

Like any web service, the server necessarily observes the connection it answers (for example, the client address used for rate limiting abuse protection). That operational handling exists to keep a paid-search endpoint from being exhausted, not to profile visitors.
